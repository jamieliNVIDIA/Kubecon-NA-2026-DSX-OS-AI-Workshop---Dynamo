What is Dynamo

Engines optimize the GPU. Dynamo optimizes the system around them.

Open sourceRust + Python · Apache 2.0 · pip, containers, Kubernetes
Any enginevLLM · SGLang · TensorRT-LLM, and more
Modularscheduling, memory, data transfer as separate crates and wheels
Solves: disaggregation · config search · traffic spikes · fault tolerance beyond Kubernetes
  • Dynamo is an open-source, high-throughput, low-latency inference framework for generative AI in distributed environments (docs, Introduction).
  • It takes an operating-systems approach: foundations for scheduling, memory management and data transfer, shipped as Rust crates and pip wheels that work together but can be adopted separately. No vendor lock-in.
  • Problems it addresses: engines only optimize a single forward pass; disaggregated prefill/decode needs scheduling, KV memory management and fast transfer; parallelism configs take days of sweeps; static configs fail on traffic spikes; LLM serving needs fault tolerance beyond standard Kubernetes.

  • Performance: Dynamo makes the engine do less work per token. The router sees exactly which KV blocks each worker holds (KV events) and weighs that against load; prefill and decode can run on separate pools; KV is offloaded to cheaper tiers instead of evicted. Proof (published): Baseten, GLM-5.2: "we observed 2x higher tokens per second on disaggregated inference" vs aggregated (head-to-head; hardware not stated).
  • Scalability: Planner autoscales prefill and decode separately against TTFT/ITL targets; Grove gang-schedules whole multi-node instances with topology awareness; Snapshot and ModelExpress make new workers serve in seconds. Proof (published): Photoroom cut GPU cold starts from ~220 s to 35–45 s with Dynamo Snapshot.
  • Resiliency: failures are routine at scale. Bad workers are detected in seconds (inhibition, discovery, canaries); in-flight streams migrate with their tokens; every router replica is active and rebuilds from worker events; KVCR-Guard and GMS keep KV and weights through engine crashes. Proof (internal benchmark): KVCR-Guard P95 TTFT during failover 26.5 s → 9.65 s.

Scheduling & scaling

Grove: schedule whole inference systems

A Kubernetes API that describes a whole inference system — frontend, prefill, decode — as one custom resource. Unlike LeaderWorkerSet, which groups one leader with its workers, Grove gang-schedules, scales and orders every role together.

  • 1
    Scale at every levela role, a group, or the whole system
  • 2
    Hierarchical gang schedulingleader + workers start together or not at all
  • 3
    Topology-aware placementpack in one rack, spread replicas apart
