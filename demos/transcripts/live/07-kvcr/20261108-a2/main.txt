================================================================
1/5  One repository, two agents
The main agent read a large repository on A; its subagent lands on B, which has spare compute.
================================================================
The main agent has read a whole repository on A. It forks a subagent with the same context and a
new task. The subagent lands on B, which has spare compute but has never seen the repository.

$ cat kvcr-settings.yaml
workers:
- name: A
  GPUs: 2
  node: cp-0198
- name: B
  GPUs: 2
  node: cp-0124
agents:
  main agent: on A, reads the whole repository
  subagent: on B, same repository plus its own task
context_window_tokens: 65536
state_path:
- A GPU
- A host pool
- B host pool
- B GPU
kv_transfer:
  connector: OffloadingConnector
  tier: kvcr
  host_pool_per_worker: 4 GiB
  transport: NIXL / LIBFABRIC / EFA
routing: Requests pinned to A and B by hand; choosing B automatically is the router's
  job.
runtime: Experimental pinned Dynamo nightly + vLLM/KVCR adapter.
