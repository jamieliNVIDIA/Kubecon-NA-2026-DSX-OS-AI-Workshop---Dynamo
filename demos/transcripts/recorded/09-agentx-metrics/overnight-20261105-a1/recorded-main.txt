2/3  What did a user experience?
Read first-content latency, inter-token latency and per-request generation rate.
================================================================

$ cat user-metrics.txt
RECORDED: user-visible latency and active generation

Accepted measured requests                      122
Reported request errors                           0
TTFT p50 / p99 (ms)                  306.19 /  2150.72
ITL p50 / p99 (ms per token)            6.99 /    11.42
Mean decode tokens/s/request                 139.79

TTFT: request start -> first content chunk.
ITL: (last content time - first content time) / (output tokens - 1).
This run assumes one token in the first chunk; per-chunk usage was off.
Rate per request = 1 / ITL_seconds; the shown mean averages those rates.
ITL percentiles summarize request-average gaps, not all token gaps.
These generation rates exclude TTFT, queueing before first content,
and tool waits. They are not end-to-end agent speed.

Canonical output tokens/s                     81.16

Admission / grace bound: 900 / 300 s
Canonical rate denominator: 1200.00 s

Aggregate rate = completed output tokens / canonical observation window.
Per-GPU rate divides that observed rate by the two assigned H100s.
Tool waits and drain count here; this is not peak GPU capacity.
Prompt totals include repeated context; cache-read is server-reported.
More cache reuse saves prefill work, not generation of each new token.
Do not divide aggregate rate by C4 to infer generation speed per user.
Scaling asks how these measures change as load grows. No curve is
inferred from this single low-load observation.
